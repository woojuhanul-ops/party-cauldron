# Spec — Integrated Kitchen System (Party Cauldron)

> Kiro spec-driven development 문서. 이 스펙이 MVP의 요구사항·설계·작업 목록의 단일 기준이다.

## 1. 개요

냉장고에 무엇이 있고, 언제까지 먹어야 하고, 그것으로 무엇을 만들 수 있는지를 하나의
오프라인 웹앱으로 잇는다. 서버·외부 API 없이 정적 파일만으로 동작하며, 모든 기록은
사용자 브라우저의 localStorage에만 저장된다.

## 2. 요구사항 (Requirements)

### R1. 입고·유통기한 엔진
- 사용자는 재료 이름·수량·단위·입고일을 등록할 수 있다.
- 시스템은 재료별 표준 보관일수(내장 표 30종 이상)를 이용해 유통기한을 자동 계산한다.
- 목록은 남은 일수가 적은 순으로 정렬되고, 3일 이내 임박과 만료가 시각적으로 구분된다.
- 표에 없는 재료는 기본 7일을 적용하고 그 사실을 표시한다.

### R2. 레시피 대조
- 내장 레시피 40개 이상(재료 목록 포함)을 보유 재료와 대조한다.
- 부족 재료 0개는 "지금 만들 수 있어요", 1~2개는 "이것만 사면 가능해요"로 분리 표시한다.
- 전체 레시피를 접이식 목록에서도 볼 수 있다.

### R3. 장보기 목록
- 레시피의 부족 재료를 한 번의 클릭으로 장보기 목록에 모을 수 있다(중복 제거).
- 항목은 체크하면 취소선으로 완료 표시되고 되돌릴 수 있으며, 항목별 삭제와 전체 비우기가 가능하고, 목록은 localStorage에 유지된다.

### R4. Party Cauldron (인원 배율)
- 인원 슬라이더(1~20명)를 움직이면 모든 레시피 카드의 재료량이
  (선택 인원 ÷ 레시피 기준 인분) 배율로 즉시 재계산되어 표시된다.
- 슬라이더 값은 새로고침 후에도 유지된다.

### R5. 공통
- 한국어 기본, 한/영 전환 토글. 모바일 반응형.
- 프레임워크·빌드 도구·외부 API 금지(순수 HTML/CSS/JS).

## 3. 설계 (Design)

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 구조(입력 폼, 재고, 레시피, 장보기, 파티 슬라이더) |
| `style.css` | 반응형 스타일, 상태 배지(여유/임박/만료) |
| `data.js` | 표준 보관일수 표(57종), 레시피 47개, Node 검증용 export 가드 |
| `app.js` | 상태(localStorage), 유통기한 계산, 레시피 대조, 렌더링, i18n |

핵심 계산:
- `expiry = 입고일 + 표준 보관일수`, `daysLeft = expiry − 오늘` (날짜 단위 비교)
- 레시피 배율 = `party ÷ recipe.servings`, 수량은 0.25 단위 반올림(10 이상은 정수)

## 5. 수용 기준

- 오프라인에서 `index.html`을 열면 전 기능이 동작한다.
- `node --check data.js app.js` 통과, 레시피 ≥ 40, 보관표 ≥ 30.
